## 7. 环境约束与处理（非代码缺陷）

| 编号 | 现象 | 处理 |
|---|---|---|
| E-01 | 系统 JAVA_HOME 指向不存在的目录 | 构建时显式 export 正确 JDK21 路径 |
| E-02 | Docker Desktop 未启动 | 手动拉起并等待 daemon 就绪 |
| E-03 | Docker Hub 直连不可达（registry-1.docker.io EOF） | mysql/qdrant/minio 经 DaoCloud 镜像代理拉取；redis/rabbitmq 复用本地镜像；compose 以 `DOCKER_MIRROR` 变量支持可配置代理 |
| E-04 | 宿主机 3306 被本地 MySQL 占用 | 容器 MySQL 不对宿主机暴露端口，backend 走容器网络访问（互不干扰） |
| E-05 | 冒烟脚本在 Git Bash 下 curl 直发中文 JSON 按 GBK 编码，后端 UTF-8 解析报"请求体格式错误" | 脚本改为 UTF-8 临时文件 + `--data-binary @file`；前端浏览器不受影响（浏览器始终以 UTF-8 发送） |
| E-06 | 后端统一返回 HTTP 200 + 业务码，冒烟最初按 HTTP 状态码断言 | 脚本改为业务码断言；安全拦截（401/403/429）仍为 HTTP 状态码 |

## 8. 缺陷记录与修复

| 编号 | 级别 | 现象 | 根因 | 修复 | 回归 |
|---|---|---|---|---|---|
| C-05 | P2 | SQL 护栏对 INSERT 仅报"仅允许 SELECT"而非"禁止关键字" | 校验规则顺序：SELECT 前缀检查先于关键字检查 | 调整校验顺序（关键字 → 前缀 → 表白名单） | 单测通过 |
| C-06 | P1 | 检索排序完全倒置（磁盘问题命中 CPU 手册） | Spring AI 约定 metadata `distance` 为距离（越小越相似），实现误当相似度 | `semantic = 1 − distance` 并夹取 [0,1] | RetrievalServiceTest 5/5 |
| BUG-01 | P2 | 前端诊断报告引用知识库片段显示字面 `\n` 与多余引号 | Spring AI 默认 ToolCallResultConverter 对 String 返回值再做一次 JSON 序列化（首尾引号 + `\n` 转义），SSE/落库/剧本引用均携带转义文本 | 新增 `ToolResultUnwrapper`（剥多层 JSON 包装 + 还原转义），在编排器 tool_result 事件、tool 消息落库、Mock 剧本 squeeze 三处统一解包；补 5 个单测 | 43/43 + 浏览器复验渲染正确 |
| BUG-02 | P1 | backend 容器重启后前端 API 全部 502 | nginx 启动时静态 `proxy_pass http://backend:8080` 缓存首次 DNS 解析，容器 IP 变化后失效 | nginx 配置 Docker 内置 DNS 动态解析：`resolver 127.0.0.11 valid=10s` + 变量 upstream | 浏览器复验对话链路正常 |
| C-07 | P3 | 编译期问题 4 项：Spring AI 1.0 无 `ToolCallbacks` 工具类（改用 `MethodToolCallbackProvider`）、`ChatOptions` 包路径、`Embedding` 构造器顺序、qdrant client 将 grpc 声明为 runtime 作用域 | 对 1.0.0 API 认知偏差 | 按 javap 实测签名修正；pom 显式补充 grpc-api(compile) | 编译+全量测试通过 |

> 缺陷密度参考：交付约 1.9 万行代码（前后端），有效缺陷 7 项（P1×2 / P2×2 / P3×3），全部修复并回归，无遗留阻断问题。
